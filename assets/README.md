# Assets

This directory stores reusable fonts, images, music, sound effects, and battery profiles, organized by asset type.

Keep each asset in the matching subdirectory and document its destination, naming, integration method, and source/license. Do not mix binary assets with Markdown documentation.

## Fonts

Store reusable font files and generated font sources in `fonts/`.

- Use descriptive names that include the family, weight, size, and format when relevant.
- Document the source, license, character range, conversion command, and expected destination.
- Check Flash and internal-RAM impact before adding a font; the ESP32-C3 has no PSRAM.
- Do not commit fonts whose license does not permit redistribution.

### eCard UI fonts

[`fonts/`](fonts/) contains the five LVGL bitmap fonts used by the eCard UI:
`ecard_font_9.c`, `ecard_font_12.c`, `ecard_font_16.c`, `ecard_font_22.c`,
and `ecard_font_48.c`. They are compiled into `main` by `main/CMakeLists.txt`
and selected explicitly by every text widget in `main/ecard_ui.c`.

| Item | Value |
| --- | --- |
| Source family | Noto Sans CJK SC Regular, tag `Sans2.004` |
| Source URL | `https://github.com/notofonts/noto-cjk/raw/Sans2.004/Sans/OTF/SimplifiedChinese/NotoSansCJKsc-Regular.otf` |
| Source SHA-256 | `2c76254f6fc379fddfce0a7e84fb5385bb135d3e399294f6eeb6680d0365b74b` |
| License | SIL Open Font License 1.1, [`fonts/LICENSE-NotoSansCJK.txt`](fonts/LICENSE-NotoSansCJK.txt) |
| Converter | `lv_font_conv` 1.5.3, `--bpp 2 --format lvgl --no-compress` (2 bpp keeps four antialiasing levels and halves the bitmap payload) |
| Coverage | printable ASCII + every non-ASCII character literally used by the eCard sources + the UI symbol set; 12/16/22 px also include GB2312 level-1 so user-entered school, class, and name render correctly; 9 px and 48 px are ASCII-only |
| Compiled size | roughly 1.0 MiB of font data in Flash; the application is 2.66 MB in a 4.03 MB OTA slot |

Regenerate the checked-in sources from the repository root:

```bash
npm install --prefix /tmp/lvfont lv_font_conv@1.5.3
python3 tools/generate_ecard_fonts.py \
  --converter /tmp/lvfont/node_modules/.bin/lv_font_conv
```

The script downloads the pinned OTF into `fonts/.cache/`, verifies its SHA-256,
and fails if the source font lacks a requested glyph. The cached OTF is not
committed. After changing UI text, rerun the script and
`python3 tests/test_ecard_fonts.py`; `./tools/validate.sh --static` also runs
the coverage test. Characters outside the generated inventory are unsupported
and render as LVGL's missing-glyph placeholder.

Regenerate the portrait descriptors from the repository root after replacing the source image:

```bash
python3 tools/generate_ecard_photo.py
```

- Use descriptive names and document dimensions, pixel format, conversion steps, and destination.
- Prefer formats suitable for the 240 × 320 RGB565 display and account for Flash and internal RAM.
- Preserve editable sources where licensing permits, and record the source and license.
- Never commit device QR secrets, credentials, or personal data in images.

## Music and sound effects

Store reusable music and sound-effect sources in `music/`.

- Document the source, license, sample rate, bit depth, channels, conversion command, and destination.
- Prefer 16 kHz, 16-bit mono PCM when it matches the current BSP audio path.
- Check Flash and internal-RAM cost before embedding audio; stream or chunk long recordings.
- Do not commit media without redistribution permission.

### eCard demo voice

[`sounds/ecard_demo_voice.c`](sounds/ecard_demo_voice.c) is a 7.3 s demo
message used while network voice messages carry no audio payload. It is 4-bit
IMA-ADPCM at 16 kHz mono, starts from decoder state 0/0, and costs about
59 KB of Flash.

| Item | Value |
| --- | --- |
| Text | Chinese demo line rendered locally by the generator (a mother's reminder to a pupil) |
| Voice | macOS `say -v Tingting` (zh_CN), a synthetic placeholder, not a real person |
| Generator | `python3 tools/generate_ecard_demo_voice.py` (needs macOS `say`/`afconvert`) |
| Destination | Compiled into `main` by `main/CMakeLists.txt`; playback handled by `main/ecard_voice.c` |

Treat this clip as a demo placeholder and replace it with Xiaozhi TTS audio
once the streaming backend is connected.

## Battery profiles

[`battery/wanli-500mah-profile2-xil40x-20261020.txt`](battery/wanli-500mah-profile2-xil40x-20261020.txt)
contains the supplied CW2017 profile for the Wanli New Energy 500 mAh cell
(profile2, XIL40X, 2026-10-20). It is an unchanged copy of the project-supplied
file, retained at the maintainer's request for this firmware update. Its
original filename is recorded in the paired Chinese document. No separate
license was included in the supplied file.

The format is 80 lines of two hexadecimal digits, one byte per line in register
order. The BSP embeds those bytes in `components/bsp/src/bsp_battery.c`; the
host gate checks the source file and initializer for an exact match. Text-file
SHA-256: `7ea96eba4634f4495a37c25ffacd54c1deaa0693b162c892d671a2ba68460919`.
Decoded 80-byte SHA-256:
`fa7365671093ef449c5bdcfb4adb279e3d275f888109f50b6b2f21e9b96220d5`.
This is a fuel-gauge profile, not a charging configuration or a generic profile
for every 500 mAh cell; see the [hardware guide](../docs/hardware-design/AI_HARDWARE_DEVELOPMENT_GUIDE.md#9-cw2017-fuel-gauge).
